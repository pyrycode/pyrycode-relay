# Ticket #95 — tighten cert cache dir to 0700 when owned by relay's runtime uid

Narrow exception to the "loud failure over silent correction" project rule for `ErrCacheDirInsecure` (#9): when the cache dir exists at broader-than-0700 perms and is owned by the relay's own runtime euid, `NewAutocertManager` now tightens it to 0700 in place (one INFO log line) and continues startup. Foreign-uid (or ownership-unknown on non-Linux) preserves the existing loud-rejection path untouched. Motivated by Fly.io's `[[mounts]]` block having no `mode` field — Fly remounts the volume at 0755 on every machine boot, which previously tripped `ErrCacheDirInsecure` and forced a non-obvious subdir-of-mount workaround in `fly.toml`.

## Implementation

- **`internal/relay/tls.go` (modified, +30/-4)** — `NewAutocertManager`'s `default:` branch now consults `fileOwnerUID(info)` when `mode & 0o077 != 0`. Same-uid → `os.Chmod(cacheDir, 0o700)` (returns a new wrapped `"relay: tightening cert cache dir ..."` error if chmod itself fails — the dir is in an undefined perm state and starting up would be wrong) followed by `slog.Default().Info("tightened cert cache dir perms", "path", cacheDir, "from", fmt.Sprintf("%#o", mode), "to", "0700")` *after* a successful chmod so a failed chmod cannot produce a misleading "tightened" line. Foreign-uid / `!ok` → unchanged `fmt.Errorf("%w: %s (mode %o)", ErrCacheDirInsecure, cacheDir, mode)`. Doc comments on `ErrCacheDirInsecure` and `NewAutocertManager` rewritten to reflect the narrowed contract; the sentinel's wire identity (`errors.Is` matching, formatted message including path + mode) preserved.
- **`internal/relay/owner_linux.go` (new, 19 lines, no build tag)** — Linux entry point (auto-applied by filename suffix per [ADR-0009](../decisions/0009-build-tag-platform-split-convention.md)). `fileOwnerUID(info os.FileInfo) (uint32, bool)` type-asserts `info.Sys().(*syscall.Stat_t)` and returns `(st.Uid, true)` on success, `(0, false)` on assertion failure (defensive against future stdlib changes; unreachable on linux/amd64 + linux/arm64 today).
- **`internal/relay/owner_other.go` (new, 11 lines, `//go:build !linux`)** — non-Linux stub returning `(0, false)`. Routes callers into their existing "ownership unknown" branch — for `NewAutocertManager` that is the unchanged `ErrCacheDirInsecure` rejection. Keeps darwin dev runs as a strict superset of pre-#95 behaviour.
- **`internal/relay/log_allowlist.go` (+3 keys)** — adds `path`, `from`, `to` to `allowedLogKeys` in the same commit as the new call site, satisfying `TestLogKeysAreAllowlisted` (#36's commit-time gate against unallowlisted structured-log keys).
- **`internal/relay/tls_test.go` (+46/-12)** — replaces the existing `TestNewAutocertManager_ExistingInsecureDirRejected` (its semantic role flipped: same 0o755-in-`t.TempDir()` setup now exercises the *tightening* path) with three new tests:
  - `TestNewAutocertManager_OwnedInsecureDirIsTightened` (Linux-only, skip elsewhere) — AC1: 0755 dir owned by test process uid → no error, post-call mode is 0700.
  - `TestNewAutocertManager_ForeignOwnedInsecureDirRejected` (Linux + root only, skip otherwise) — AC2: 0755 dir `Chown`'d to uid 65534 → `errors.Is(err, ErrCacheDirInsecure)` AND post-call mode unchanged at 0755 (chmod must not have run).
  - `TestNewAutocertManager_InsecureDirRejectedOnNonLinux` (skip on linux + windows) — locks the strict-superset property: darwin still rejects 0755 dirs because the stub returns ownership-unknown.

## Acceptance criteria — verification map

- **AC1** (same-uid 0755 → tightened, no error, startup continues): `tls.go:59-71`; `TestNewAutocertManager_OwnedInsecureDirIsTightened`.
- **AC2** (foreign-uid 0755 → `ErrCacheDirInsecure` preserved): `tls.go:60-63`; `TestNewAutocertManager_ForeignOwnedInsecureDirRejected` (root-gated; the architect's call to skip-gate rather than design a uid-switching helper).
- **AC3** (symlink or non-dir at cache path → existing rejection paths unchanged): no edits to the `IsDir` check or `os.Stat` behaviour; existing `TestNewAutocertManager_CacheDirPathNotADirectory` unchanged. `os.Stat` follows symlinks; a symlink to a 0755 same-uid dir now follows the new tightening path (`os.Chmod` follows symlinks identically), which is acceptable per the spec — the AC's "existing rejection paths" wording covers structural unchanged-ness, not any new symlink-specific behaviour.
- **AC4** (real-Fly deploy with mount-root cache dir starts cleanly): operator-verified post-merge. `fly.toml:27` already uses the mount root on `main`; no `fly.toml` edit shipped with this PR.

## Patterns established

- **Narrow, ownership-gated exceptions to "loud failure over silent correction" are acceptable when the same-vs-foreign-uid split is the trust invariant.** The relay's project rule (`docs/PROJECT-MEMORY.md` § Project-level conventions) names `ErrCacheDirInsecure` as the canonical example of fail-loud. #95 carves out *one* substrate-specific exception (same-uid 0755 dir = "the kernel just handed our process a freshly mounted dir at standard volume perms"; foreign-uid 0755 dir = "someone else staged TLS-key storage at our path"). The exception is scoped to that exact trust invariant; not a general relaxation. Apply the same shape only when the gate is similarly load-bearing — generalising would erode the rule's value.
- **`_<goos>.go` / `_other.go` second instance, no new exported symbols.** First instance was #79's `caps_linux.go` / `caps_other.go` ([ADR-0009](../decisions/0009-build-tag-platform-split-convention.md)). The owner-probe pair (`owner_linux.go` / `owner_other.go`) replicates that shape verbatim — tag-free Linux file, explicit `//go:build !linux` on `_other.go`, helper unexported (`fileOwnerUID`, not `FileOwnerUID`) because it is internal-only to `NewAutocertManager`. The pattern's now load-bearing — a third Linux-only probe should reach for the same shape without re-litigating the convention.
- **Log allowlist (#36) is a same-commit gate.** When adding a new `slog` call site, the new keys (`path`, `from`, `to`) ship in the same commit as the call site in `log_allowlist.go`. `TestLogKeysAreAllowlisted` AST-walks the package and would fail CI otherwise. The keys also satisfy the "operator-grep contract": the INFO log fields (`path` / `from` / `to`) are deliberately reserved as part of the contract — operators may grep on them, so the names should not drift.
- **Emit observability after the deciding syscall returns nil.** The INFO `"tightened cert cache dir perms"` line is emitted *after* `os.Chmod` returns nil, not before. A pre-chmod log line would lie if the chmod itself fails. The same instinct applies to any future "silent correction with a log line" path: the log is the post-success witness, not the pre-attempt announcement.

## Lessons learned

- **A scoped exception to a project rule beats a workaround that encodes substrate quirks into deploy manifests with no co-located explanation.** The pre-#95 workaround — pass a subdir of the mount as `--cert-cache` so `os.MkdirAll` creates the leaf at 0700 — works, but the indirection is invisible: a reader of `fly.toml` has to know about the perm check to understand the subdir. The narrowing fixes it at the layer where the trust invariant actually lives (the relay's own process), which is more honest than papering over it at the manifest layer. General principle: when a workaround requires institutional knowledge to read, the workaround is the bug.
- **Pick the coarsest seam that still avoids the system dependency — `*syscall.Stat_t` over `os.Geteuid`-injection.** The first design instinct is to make `os.Geteuid()` an injectable seam to test the foreign-uid branch in a normal `go test` run. Resisted. The branch already has the *real* system dependency (Linux `chown` requires root), and the AC2 test is root-gated regardless. Adding a seam for the same-uid path on top of an already-gated foreign-uid path would invent surface area to dodge a single `t.Skip`. The architect's call: skip-gate the AC2 test, no Geteuid seam. Apply the same instinct to any future "this test needs root" path — a clean skip beats a contrived seam.
- **A failed `os.Chmod` returns a new wrapped error, not `ErrCacheDirInsecure`.** Both errors look like "permission problem with cache dir" to a casual reader, but they have different semantics: `ErrCacheDirInsecure` means "the dir exists at insecure perms and you must fix the substrate"; a chmod-failure error means "the relay tried to self-correct and the OS refused" (e.g. a read-only mount). The two warrant different operator responses, so they ride on different error shapes. `errors.Is(err, ErrCacheDirInsecure)` returning false on a chmod failure is the contract that keeps them distinct. Carry this instinct forward to any future "loud failure split with a self-correct branch" — the self-correct's own failure mode earns its own error.
- **`TestLogKeysAreAllowlisted` is a real, structural CI gate — not a stylistic suggestion.** A first-pass developer who adds the `slog.Default().Info(...)` call without also editing `log_allowlist.go` will see a CI failure at the gate, not at code review. The fix is one-line per key in the same commit; the *anti-pattern* is to delete the test or relax the AST walker. The defence's value is exactly that it forces the key-namespace decision into the same change-set as the call site (#36).
- **Verifying the narrowing on a real Fly deploy is operator-side and lands separately from the code change.** AC4 reads "real-Fly deploy starts cleanly" — that gates production, not the merge. The code change is what enables the verification; the operator does the verification when the next deploy lands. This split is consistent with the pipeline's "code review passes, then operator drives the deploy" shape and avoids holding the merge on a Fly-specific environment that the developer's `go test` doesn't have access to.
