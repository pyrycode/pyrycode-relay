# Ticket #126 — Patch image-scan CVEs: Go 1.26.8 builder, x/net v0.59.0

Two pinned-version edits, no Go source change. Clears the nine HIGH CVEs the daily `security-scan` (Trivy image scan) reported against `stdlib@v1.26.5` (eight findings) and `golang.org/x/net@v0.55.0` (one finding, CVE-2026-46600). Third occurrence of this exact fix shape after #103 (`x/crypto v0.51.0`/`x/text v0.39.0`/Go 1.26.5 builder) and #122 (module bumps + builder digest refresh in one change).

## Implementation

- `Dockerfile` build-stage digest: `golang:1.26-bookworm@sha256:1ecb7edf…` (Go 1.26.5) → `@sha256:a688600c…` (Go 1.26.8, resolved from Docker Hub 2026-09-24). The `Tracks: golang:1.26-bookworm` comment stayed accurate, no edit needed. Distroless runtime stage untouched. Trivy's stdlib version comes from the *builder's* toolchain, not the `go 1.26.2` directive in `go.mod` — the digest refresh is what clears the eight stdlib findings, a module bump alone would not.
- `go get golang.org/x/net@v0.59.0` + `go mod tidy`, taking the current release rather than the ticket's stated minimum (v0.56.0). By MVS this also moved `golang.org/x/crypto` v0.52.0→v0.57.0, `x/sys` v0.45.0→v0.48.0, `x/text` v0.39.0→v0.42.0. No other module in the graph changed.

## Patterns established / reinforced

- **Minimum-fixed-version isn't always minimum-risk.** The architect spec found that x/net's stated minimum (v0.56.0) would still leave `x/crypto` at v0.53.0, which carries a separate HIGH CVE (CVE-2026-56854, published 2026-08-28, after the ticket's last red scan) that `ignore-unfixed` would not suppress and the next scan would catch anyway. Taking the current release (v0.59.0) landed `x/crypto` v0.57.0, clearing it in the same change instead of opening a follow-up ticket next cycle. When an MVS bump drags a second module forward, check that module's own CVE status before treating "ticket's stated minimum" as sufficient.
- **No-Docker-on-builder-host substitute proof.** The AC asked for a local `docker build` + Trivy scan; the builder host has neither. The self-review substituted: registry API confirmation of the new digest's `GOLANG_VERSION`, a `GOTOOLCHAIN=go1.26.8 go build -trimpath` + `go version -m` to get the exact embedded module/stdlib set, then an OSV `querybatch` over that set (with a control query against the old `stdlib@1.26.5`/`x/net@0.55.0` pair reproducing the original 8+1 red findings, to validate the substitute method itself). This is a verification-gap pattern worth reusing on future dependency-CVE tickets run from a scanner-less host — the real gate stays the post-merge `security-scan` `workflow_dispatch` on `main`.
