# Ticket #98 — migrate `nhooyr.io/websocket` → `github.com/coder/websocket`

Mechanical library-identity swap: the relay's WebSocket dependency moves from the deprecated `nhooyr.io/websocket` vanity import path to its maintained canonical home `github.com/coder/websocket` (v1.8.14, the latest release). Coder forked nhooyr for continued maintenance, not an API redesign, so the public types, constants, method signatures, and documented Close/Read/Write behaviour are compatible across the fork point — the change is an import-path swap across 13 `.go` files plus `go.mod`/`go.sum`, with no behavioural change to frame handling, close codes, or the upgrade flow. Unblocks the downstream plan to add `staticcheck` to `make check` (the pre-existing SA1019 deprecation errors against the nhooyr path would otherwise flood every QA run with infra-classified failures). Supersedes [ADR-0004](../decisions/0004-ws-library-and-adapter-context-strategy.md) via [ADR-0010](../decisions/0010-coder-websocket-migration.md).

## Implementation

- **`go.mod` / `go.sum`** — `nhooyr.io/websocket v1.8.17` replaced by `github.com/coder/websocket v1.8.14` (confirmed the latest released version — `go list -m -versions github.com/coder/websocket` ends at v1.8.14). No `replace` directive; `go mod tidy` rewrote `go.sum`.
- **Production (6 files)** — pure import-path swap (`"nhooyr.io/websocket"` → `"github.com/coder/websocket"`). The import alias stays `websocket` because both modules' package name is `websocket`, so every `websocket.*` qualifier (`Accept`, `Dial`, `StatusCode`, the close-code constants, `MessageBinary`, `AcceptOptions`, `DialOptions`, `CloseError`) is unchanged: `internal/relay/{ws_conn,heartbeat,shutdown,server_endpoint,client_endpoint}.go`. `cmd/pyrycode-relay/main.go` has **no import** of the WS library — only two doc-comments naming it (lines 26, 232) were updated.
- **Tests (7 files)** — the same one-line import swap, no test-logic changes: `internal/relay/{ws_conn,server_endpoint,client_endpoint,shutdown,heartbeat,metrics_upgrade}_test.go` and `cmd/pyrycode-relay/main_e2e_test.go`. The `errors.As(err, &ce)` assertion against `websocket.CloseError` in `heartbeat_test.go` works unchanged (identical type name and `Code`/`Reason` fields in coder).
- **Doc-comment library-name updates** in `ws_conn.go` (lines 16, 124) and `server_endpoint.go` (line 61) — descriptive only, no behaviour.
- **Docs:** [ADR-0010](../decisions/0010-coder-websocket-migration.md) added; ADR-0004's Status set to `Superseded by ADR-0010 (#98)` with its body left intact as historical context; [ws-conn-adapter.md](../features/ws-conn-adapter.md) library identity + *Dependency* / *Related* sections rewritten; [INDEX.md](../INDEX.md) gained the ADR-0010 pointer under *Decisions* and the WSConn feature line repointed to the new library name.

## Acceptance criteria — verification map

- **AC1** (go.mod declares coder/websocket at latest; go.sum reflects the swap; no nhooyr in either): `go.mod` require block + `go.sum` — `grep nhooyr go.mod go.sum` returns zero; v1.8.14 confirmed latest.
- **AC2** (`grep -rn "nhooyr.io/websocket" --include="*.go" .` → zero): verified zero matches across all 13 `.go` files.
- **AC3** (`make build` succeeds, `make check` passes, `go test -race ./...` green): all verified locally — both packages `ok` under `-race`; `make check` (= `vet test`) clean.
- **AC4** (WS-handshake / heartbeat / shutdown tests pass with only the import swap): verified — no test logic changed beyond the import path; full suite green.
- **AC5** (new ADR supersedes ADR-0004 naming the deprecation trigger; ws-conn-adapter.md + INDEX.md repoint): ADR-0010 + ADR-0004 status + ws-conn-adapter.md + INDEX.md all updated.

## Patterns established

- **A library-identity migration is uniformly mechanical when the fork keeps the package name.** Because coder kept `package websocket` and every public symbol's name and signature, the import alias stays `websocket` and zero call sites change — only the import string and the `go.mod` line move. The pre-swap API-surface audit (every symbol and `Conn` method the relay touches, each confirmed against coder's godoc) is the gate that earns the "uniformly mechanical" claim; it is recorded in [ADR-0010](../decisions/0010-coder-websocket-migration.md) § Rationale. The ticket's trip-wire (any renamed symbol or changed signature → halt, route to PO) never fired.
- **Superseding-ADR shape.** ADR-0010 is a lightweight migration ADR (~50 lines): Status `Accepted (#98)` plus `Supersedes: ADR-0004`; the superseded ADR-0004 keeps its full body and gains `Superseded by ADR-0010` on its Status line (mirrors the #78→#79 convention). The original *design* rationale stays in ADR-0004; the superseding ADR records only the trigger (upstream deprecation), the new version, and the behavioural-property verdicts.
- **Behavioural-property verdicts belong in the superseding ADR, never in edits to frozen lessons.** Lessons 59/77/85 are frozen (2026-05-11). Each was confirmed to survive the fork (Close-safe-with-in-flight-Write, 5s close-handshake grace, default read cap) and the verdicts recorded in ADR-0010 § Consequences — the established "new findings go in new docs" shape, not an edit to `lessons.md`.

## Lessons learned

- **Lesson 85's "32 MiB default per-frame read limit" is a frozen factual error — the real default is 32 KiB.** Verified against source: `coder/websocket@v1.8.14/read.go:107` declares `const defaultReadLimit = 32768`, and `read.go:91`'s godoc reads "By default, the connection has a message read limit of 32768 bytes" (= 32 KiB). The figure was the same in `nhooyr.io/websocket` v1.8.x (coder is a maintenance fork). ADR-0010 § Consequences documents this for the next reader. Runtime impact today: **none** — production calls `SetReadLimit(256 KiB)` in `NewWSConn` (#29) before any frame is read, so the default never reaches a routed frame, and the test fixtures that omit `SetReadLimit` send sub-32-KiB frames.
- **A consequence worth a dedicated follow-up review (flagged, not fixed here):** because the real default (32 KiB) is *below* the production cap (256 KiB), `SetReadLimit(256 KiB)` actually *raises* the per-frame limit — the inverse of the "tighten down from a 32 MiB default" framing carried in #29's reasoning, in `cmd/pyrycode-relay/main.go:191-194`'s comment, and in several feature docs. Nothing breaks today (tests pass; production sets the cap explicitly regardless of the default), so this is recorded for review rather than changed on a migration ticket. See *Out of scope*.
- **Deprecation is the ADR-reserved trigger, not an opportunistic switch.** Both `docs/lessons.md:63` and ADR-0004's last *Consequences* bullet forbade switching to the coder fork "without an ADR" / "opportunistically." Upstream *deprecation* of the vanity path — not a behavioural change in the library — is exactly the condition those artefacts reserved judgement for; ADR-0010 is the ADR they asked for. The lesson and ADR-0004's body stay frozen as historical record.

## Out of scope / follow-ups

- **Stale `nhooyr.io/websocket` name references remain in evergreen feature docs** outside AC5's narrow scope (which named only ws-conn-adapter.md + INDEX.md). Sites: `features/heartbeat.md:9,98,104`, `features/graceful-shutdown.md:5,70,143`, `features/server-endpoint.md:100,129`, `features/phone-forwarder.md:85`, `features/binary-forwarder.md:101`, `features/upgrade-and-register-failure-counters.md:94`. The *behaviour* each describes (5s close handshake, control-frame serialisation, `http.Hijacker` type-assert, default-Origin rejection) is preserved across the fork, so only the library *name* is stale — low severity. A grep-driven sweep (`grep -rln "nhooyr" docs/knowledge/features`) is the clean vehicle; deliberately not done here to keep this branch's blast radius minimal. ADRs (0004/0005/0008) and sibling per-ticket codebase notes keep their nhooyr references as historical record and should not be swept.
- **The wrong "32 MiB" figure is replicated beyond lesson 85** and should be corrected to 32 KiB in the same sweep: `cmd/pyrycode-relay/main.go:194` (comment — still reads "the library's 32 MiB default"), `features/phone-forwarder.md:85`, `features/binary-forwarder.md:101`, `features/server-endpoint.md:129`, `docs/specs/architecture/25-phone-forwarder.md:378`. Lesson 85 itself is frozen; the authoritative correction already lives in ADR-0010. The `main.go` comment is a code file and was left untouched under this ticket's "pure migration — do not refactor adjacent code" scope.
- **`staticcheck` in `make check`** — the downstream ticket this migration unblocks. Out of scope here by design.
