# Ticket #113 — Per-phone bounded delivery queue so a slow phone can't block the fan-out

`StartBinaryForwarder` used to write each routed frame to a phone with a synchronous `phone.Send`, bounded only by `writeTimeout` (10s). A phone that stopped reading held the binary's whole read loop for up to 10s per frame — freezing delivery to every other phone on the same server-id and starving the binary's own pong processing (issue #140), which since [#112](112.md) could widen into a live incumbent losing its slot to a concurrent conflicting claim. Each phone is now registered behind a `phoneOutbox`: a 16-frame FIFO drained by the phone's own writer goroutine. The forwarder only enqueues — an operation that never blocks — so a stalled phone can no longer hold up anything but itself.

## Implementation

- New `internal/relay/phone_outbox.go`: `phoneOutbox` wraps a phone `Conn` with a bounded channel (`items`, capacity `phoneOutboxDepth = 16`) and a `done` channel closed exactly once via `sync.Once`. `Enqueue(frame []byte, closeCode uint16) error` never blocks — full queue or already-stopped both return a sentinel (`ErrPhoneBacklogFull`, `ErrPhoneOutboxClosed`) instead of waiting. `run()` is the single per-phone writer goroutine; it drains `items` in order, delivering frames via `conn.Send` and close directives via `closePhone`, so a directive takes effect only after every frame queued before it. `Close`/`CloseWithCode` stay immediate (not queued) and delegate straight to the wrapped conn, preserving the `gracefulCloser` capability that registry eviction (`4404`), grace expiry, and `Shutdown` (`1001`) all type-assert for.
- `internal/relay/forward.go`: new `phoneQueue` interface (`Enqueue(frame []byte, closeCode uint16) error`), consumer-defined like the existing `phoneCloser`. `StartBinaryForwarder` type-asserts the addressed phone against it after the `PhonesFor` lookup; a match enqueues and continues, logging `binary_forwarder_phone_enqueue_failed` on refusal. The prior direct-`Send` / direct-`closePhone` branches are unchanged as source but now serve only `fakePhone`-style test doubles, since every production phone is a `*phoneOutbox`.
- `internal/relay/client_endpoint.go`: `ClientHandler` constructs and registers a `*phoneOutbox` in place of the bare `*WSConn`, starts `run()` on its own goroutine after registration, and the teardown defer becomes `UnregisterPhone` → `wsconn.Close()` (aborts any in-flight write) → `phone.stop()` → wait on an `outboxDone` channel before returning. The wait is what makes "nothing outlives the connection" structural rather than a race.
- `internal/relay/server_endpoint.go`: `conflictProbeTimeout`'s doc comment rewritten to justify the 10s value against the new reality — phone writes no longer run on the forwarder, so a live incumbent's pong waits at most for one binary read plus an enqueue. The value itself is unchanged.
- No new log keys: the drain loop reuses `binary_forwarder_phone_send_failed`, `binary_forwarder_close_frame_send_failed`, and `binary_forwarder_phone_closed`; the one new event name (`binary_forwarder_phone_enqueue_failed`) reuses existing allowlisted fields (`server_id`, `conn_id`, `err`).
- Docs updated: [`binary-forwarder.md`](../features/binary-forwarder.md) (Concurrency model, "deliberately does NOT do", Adversarial framing, logging table), new [`phone-outbox.md`](../features/phone-outbox.md) feature doc, [`threat-model.md`](../../threat-model.md) § DoS resistance (pong-starvation residual resolved, new per-phone/per-server-id memory figures), [`security-followups.md`](../../security-followups.md) (#140 entry removed — no longer deferred).

## Patterns established

- **A consumer-defined optional capability with a synchronous fallback, twice now.** `phoneQueue` (this ticket) mirrors `phoneCloser` (#119): both are single-method interfaces declared in `forward.go`, type-asserted against whatever `Conn` the registry handed back, with the non-asserting branch as a working fallback rather than a dead code path. This is now the established shape for "most Conns support X, but the interface shouldn't force every test fake to."
- **Wrap, don't replace, when the wrapper must keep a capability the registry relies on.** `phoneOutbox` implements `Conn` by delegation and re-exposes `CloseWithCode` explicitly — dropping it would have silently downgraded eviction and shutdown close codes to a generic `1000` with no test catching it, since the registry only ever calls through the type-asserted `gracefulCloser` interface, never a concrete type.
- **Guard an async side-effect goroutine's spawn point with the same `sync.Once` that marks the state transition.** `Enqueue`'s overflow branch only spawns its closing goroutine on the call where `markDone()` reports it was first — one `bool`-returning `sync.Once` wrapper serves both "did shutdown already happen" and "should I be the one spawning the closer," so repeated overflows can't multiply goroutines. Flagged as a `SHOULD FIX` in the architect's own security review and implemented before the verifier pass, not after.

## Lessons learned

- The wrapper has to keep `CloseWithCode`. Registry eviction (`4404`) and `Shutdown` (`1001`) look for code-aware close via a `gracefulCloser` type assertion. A wrapper that implemented only `Conn` would silently downgrade both to a plain `1000` close, and no existing test would go red — the failure mode is invisible until an operator notices the wrong close code on the wire.
- If the outbox's `Send` just enqueues, a test that only checks "a slow phone doesn't block its siblings" can pass even without the forwarder's `phoneQueue` type-assertion change actually wired in. The test that really exercises the new branch is the one checking that a close directive waits for the frames queued before it — ordering, not just non-blocking, is the load-bearing assertion.
