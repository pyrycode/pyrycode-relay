# Ticket #96 — configurable listener addresses for the autocert HTTP-01 and TLS listeners

Two new operator flags on the autocert path (`--http-listen`, `--https-listen`) let substrate-portable deploys (distroless/nonroot containers, K8s restricted SCC, unprivileged systemd) bind to high internal ports while the substrate forwards external 80/443. Defaults preserve today's `:443` / `:80` binding exactly — no existing deploy needs flag changes. Motivated by the first-deploy Fly bootstrap on 2026-05-24 failing at autocert listener startup with `bind: permission denied` after sibling #95's cert-cache fix unblocked the earlier gate: the distroless image runs uid 65532, and uid != 0 cannot bind ports < 1024 without `CAP_NET_BIND_SERVICE`. The flag-based path is substrate-portable; the considered `setcap CAP_NET_BIND_SERVICE` alternative bakes a Linux-kernel-only assumption into the image and was rejected.

## Implementation

- **`cmd/pyrycode-relay/main.go` (modified, +30/-5)** — two new `fs.String` declarations adjacent to `insecureListen`. Defaults are the literal `":443"` / `":80"` they replace, so AC2's "absence-of-flag preserves today's binding" property falls out of the flag-package defaults rather than a separate code branch. Help text on both flags calls out (a) "used only when `--domain` is set" so an operator reading `--help` understands the autocert-only constraint and (b) "host:port" so they don't pass a bare port (which `ListenerPort` rejects). The two literal `Addr:` fields in the autocert-branch `*http.Server` literals (lines 264 and 274) now dereference `*httpsListen` / `*httpListen`; every other field of both structs (`ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout`, `Handler`, `TLSConfig`) is preserved verbatim. The `expected` port set for the surplus-listener gate at line 297 is parameterised: `{443: {}, 80: {}}` → `{httpsPort: {}, httpPort: {}}`, sourced from the same `ListenerPort` parse that already produces the `actual` set — both sides of the asymmetric check now derive from operator input, matching the insecure-branch shape that was already this way.
- **`cmd/pyrycode-relay/main.go` mutex guard (AC3, +13)** — new inline `fs.Visit`-based guard slotted immediately after the existing line-72 `--domain ⊕ --insecure-listen` block. Refuses (`logger.Error` + exit 2) when `--insecure-listen` is set alongside either new flag *explicitly set on argv*. The `fs.Visit` choice over value comparison is load-bearing: an operator who passes `--http-listen=:80` (the default) alongside `--insecure-listen=:8080` is still confused and deserves the fast-fail — value comparison would let that case slip through silently. The error message names the flags and carries a `fix` field that explains both valid modes (proxy-fronted plaintext vs. autocert) so the operator can self-route. The guard is inline rather than extracted into a `Check…` helper in `internal/relay/` because the predicate needs no external seam (it's pure boolean logic over `*flag.FlagSet` state); extracting would require passing the `*flag.FlagSet` as a parameter — strictly more wiring than the inline form. This is the second inline mutex in `run()`, mirroring the line-72 precedent's shape.
- **`cmd/pyrycode-relay/main_e2e_test.go` (+90)** — `TestRun_InsecureMutexWithAutocertListenFlags`, a table-driven e2e test covering the AC3 mutex with three failure rows (`insecure+http-listen`, `insecure+https-listen`, `insecure+both`, each expecting exit 2) plus a control row (`insecure-alone-control`, expecting exit 0 after signal-cancel) that locks in that the mutex does NOT fire when only `--insecure-listen` is set. The failure rows skip the `freePort()` + `waitForDial` dance because the guard returns 2 *before* any listener is constructed — the test branches on `controlListener` to decide whether to start the cancel/wait sequence. All rows pass `--metrics-listen=""` (empty-string opt-out) so `NewMetricsServer` returns `(nil, nil)` and the test doesn't need a second `freePort()` for the metrics listener.

No new exported symbols. No edits to `internal/relay/`. No edits to `fly.toml` (sibling #97 owns the substrate-config change). No edits to `docs/deploy.md` (also #97).

## Patterns established

- **Inline mutex guard vs. extracted `Check…` helper — the seam-need test.** The codebase now has two clear instances of each side of the split. Inline mutex (line 72's `--insecure-listen ⊕ --domain`, this ticket's `--insecure-listen ⊕ --http-listen/--https-listen`) is the shape for predicates that are pure boolean logic over `*flag.FlagSet` state with no external system dependency. Extracted `Check…` helpers (`CheckInsecureListenInProduction`, `CheckRunningAsRoot`, `CheckCapabilities`, `CheckSingleInstance`, `CheckEnvConfig`, `CheckListenerPorts`) are the shape for predicates that need an injectable seam — env var, `geteuid`, syscall — so unit tests can drive the matrix without mutating process state. The decision rule: if extracting would require passing the `*flag.FlagSet` itself as a parameter (or its `Visit` projection), the predicate belongs inline; the helper would invent surface area without adding testability. Coverage for inline guards lives as a thin `cmd/pyrycode-relay/main_e2e_test.go` table row asserting the exit code, never as a unit test on a fabricated seam.
- **`fs.Visit` for "was this flag explicitly set"; never value comparison.** Comparing `*httpListen != ":80"` would let `--http-listen=:80 --insecure-listen=:8080` slip past silently (the operator did pass the new flag; they just happened to pass its default). `fs.Visit` walks only flags set on argv — the idiomatic Go signal for the "explicit setting" semantics this kind of mutex requires. Apply the same instinct to any future "did the operator actually pass this flag" branch.
- **Boot-time refusal sentinels use exit 2; runtime listener errors use exit 1.** The mutex returns 2, matching the established `run()` convention (#9 / #77 / #78 / #79 / #81 / the existing line-72 guard). Exit 1 is reserved for `ListenAndServe` returning a bind/accept error post-boot. Distinct codes let ops dashboards split "deploy never started because of misconfiguration" from "deploy started and then crashed" — preserved here.
- **Parameterising a hardcoded boot-check expected set follows the insecure-branch precedent.** The insecure branch already built `expected` from `ListenerPort(*insecureListen)`; the autocert branch's `{443, 80}` literal was the last hardcoded boot-check set in this file. Both branches now feed `CheckListenerPorts` from operator-configured values via the same `ListenerPort` shape — the listener-allowlist gate (#81) is fully flag-derived. Future ticket adding a new operator-configurable listener flag should drive both the `actual` and `expected` set membership from `ListenerPort(srv.Addr)`, never from a literal.
- **`http.Server` `Addr:` substitution preserves every other field by construction.** The substitution is mechanical: only the `Addr:` field changes; `ReadHeaderTimeout` / `ReadTimeout` / `WriteTimeout` / `IdleTimeout` / `Handler` (`EnforceHost(*domain, mux)` on the TLS terminator, `mgr.HTTPHandler(http.NotFoundHandler())` on the HTTP-01 listener) / `TLSConfig` (`relay.TLSConfig(mgr)`) are untouched. Worth noting at review-time as the structural invariant: a bind-address generalisation MUST NOT smuggle in a policy-field change. The PR diff is the audit surface.

## Lessons learned

- **A bind-address generalisation is one of the safest "configurable knob" tickets you can ship.** No new code path; no new validation logic; no new sentinel; no new test seam. The change is two `fs.String` declarations, one inline guard, two `Addr:` substitutions, and one `expected`-map substitution — all of which preserve today's defaults exactly. The reason this works: the wider system was already parameterised. `ListenerPort` already validated the autocert-branch addresses; `CheckListenerPorts` already accepted operator-derived sets in the insecure branch. The ticket just propagates an existing shape into the one remaining literal site. Generalisation that lands cleanly is generalisation where the surrounding code already speaks the shape; if a "configurable knob" ticket needs new validation infrastructure to land, that's a signal that the spec needs to back up and ship the infrastructure first.
- **The new flags' defaults double as a regression backstop.** AC2 mandates that `--http-listen=:80` / `--https-listen=:443` defaults preserve current behaviour. This is not just a backward-compat nicety — it means the misconfiguration "operator omits the new flags on a nonroot deploy" still produces today's `bind: permission denied` runtime failure, exactly as observed on 2026-05-24. The ticket is a capability extension, not a substrate-detect. Operators of root-or-`CAP_NET_BIND_SERVICE`-granted deploys see zero behavioural change; operators of nonroot deploys see the same failure they saw before until they explicitly opt into the high-port pattern. The default-preserving shape is what makes the change shippable independently of #97's deploy-manifest change.
- **`fs.Visit` over value-comparison was the architect's call, not the developer's defensive instinct.** The temptation as a developer is to write `if *insecureListen != "" && (*httpListen != ":80" || *httpsListen != ":443")` — it looks like it handles the same cases. It doesn't: it admits the "operator passed `--http-listen=:80` alongside `--insecure-listen=:8080`" failure mode silently. The spec named `fs.Visit` explicitly with the "explicit setting" rationale; the architect's "why" comment in the code (`main.go:86-92`) and the spec reference are what make the choice durable against future "this could be simpler" refactor pressure.
- **An inline `cmd/pyrycode-relay/main_e2e_test.go` row is the right test shape for an inline guard.** The mutex check fires before any listener is constructed, so the test does not need `freePort()` / `waitForDial()` / cancel-context choreography on the failure rows — the table's `controlListener bool` branches cleanly between the bind-needed control row and the immediate-return failure rows. This is the same shape every other `TestRun_*` in the file uses for exit-code assertions; the new test reuses existing harness primitives (`freePort`, `waitForDial`, `drainDeadline`) without introducing helpers. Worth noting because the temptation when adding a "verify boot-time refusal" test is to invent a seam; the existing harness already exercises `run()` end-to-end, which is exactly what the assertion needs.
