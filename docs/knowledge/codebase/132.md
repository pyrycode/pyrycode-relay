# Ticket #132 — FCM sender built from the service-account secret

Ships `FCMSender` in `internal/relay/push.go`: mints an OAuth access token
from an operator-supplied Google service-account key
(`PYRYCODE_RELAY_FCM_CREDENTIALS`) and POSTs a data-only, Android-high-priority
message to FCM HTTP v1 to wake a backgrounded phone. Split from #130. Nothing
calls the sender yet — #133 (blocked by this ticket) wires the `push_wake`
routing envelope to `Send` and constructs the sender in `main`.

See [feature doc](../features/fcm-push-sender.md) for the full design and
[ADR-0011](../decisions/0011-oauth2-jwt-not-google-for-fcm.md) for the
dependency-scope decision.

## Implementation

- Two production files: `internal/relay/push.go` (new, 194 lines) and
  `internal/relay/env_config.go` (+12 lines, one new `envContracts` row).
  `push_test.go` (341 lines) and `env_config_test.go` (+41 lines) cover both.
- `parseFCMCredentials` is the single parser shared by the env validator and
  `NewFCMSender` — one place decides whether a key is usable, so the two
  callers can't drift on what "valid" means.
- New direct dependency `golang.org/x/oauth2 v0.37.0`, `jwt` subpackage only
  (not `oauth2/google`) — deliberate deviation from the ticket's Technical
  Notes, recorded in [ADR-0011](../decisions/0011-oauth2-jwt-not-google-for-fcm.md).
  `go.sum` confirms no `cloud.google.com/go/*` module was pulled in.
  `docs/threat-model.md` § Supply chain updated to list it.
- The env-var row's `validate` closure returns fixed text
  (`"not a service-account JSON key (value withheld)"`) rather than
  formatting `err.Error()` like the package's other validators do — the
  existing validators quote the offending value with `%q`, this one
  deliberately does not, because the value is a private key.

## Patterns established / reinforced

- **Shared parser between env-check and constructor.** Where a credential
  needs both a boot-time shape check and a runtime constructor, one
  unexported parse function backs both call sites (`parseFCMCredentials`
  backs both `envContracts`'s validator and `NewFCMSender`). Avoids two
  independent ideas of "valid."
- **Sentinel-only error surface for secret-adjacent parse failures.** Every
  branch of `parseFCMCredentials` returns the bare `ErrFCMCredentials`
  sentinel, never a wrapped `json.Unmarshal` or `x509.Parse*` error — those
  can echo fragments of attacker- or operator-supplied bytes. The same
  discipline applies one level up in `Send`: `oauth2.RetrieveError` (which
  formats the token endpoint's response body into `Error()`) is matched with
  `errors.As` and only its `Response.StatusCode` is kept; the error itself is
  never returned or wrapped as-is. Any future credential-parsing code in this
  package should follow the same shape — check with `errors.Is`, never surface
  the underlying formatted error.
- **Second instance of "ADR before `go.mod` edit."** ADR-0008 established the
  rule for `client_golang`; ADR-0011 is the second application, this time for
  a within-scope-narrowing decision (import only the `jwt` subpackage) rather
  than a whole-library adoption choice. The pattern holds for "which
  subpackage" decisions too, not only "which library."

## Lessons learned

- No PR-body "Lessons learned" section was present; this section is drawn
  from the architecture spec and security review only.
- The credential-parsing precedent (`isRSAPrivateKey`) duplicates part of
  `golang.org/x/oauth2/internal.ParseKey`'s private-key-decoding order (PEM,
  then PKCS#8, then PKCS#1) because that internal package cannot be
  imported. A future `x/oauth2` bump that changes the JWT signer's accepted
  key encodings would silently desync the relay's copy from the module's
  actual behaviour — nothing catches that automatically today. Worth a
  test-suite cross-check (does `jwt.Config.TokenSource` reject a key our
  `isRSAPrivateKey` accepts, or vice versa) if a future ticket touches this
  code.

## Out of scope

- APNs (iOS push).
- Wiring `push_wake` to `Send` and constructing `FCMSender` in `main` — #133.
- Telling the daemon a device token is dead; retry policy.
- Rate-limiting wakes per server-id — deferred to whichever ticket connects
  inbound frames to `Send` (#133), since only that ticket has a frame to
  rate-limit on.
